# Алиасы команд через just

Репозиторий с настройками [just](https://just.systems) и скриптами развёртывания:
общие команды приезжают на машины из git, машинные остаются на машине.

## Как устроено

На машине just работает с одним глобальным `justfile`, который импортирует три файла:

| Файл в каталоге конфигов | Что это | Откуда берётся |
| --- | --- | --- |
| `global.just` | команды для всех машин | симлинк на `Config/global.just` |
| `group.just`  | команды группы машин   | симлинк на `Config/<группа>/group.just` |
| `local.just`  | команды только этой машины | обычный файл, создаётся пустым |

Каталог конфигов — `~/.config/just` (Linux, с учётом `XDG_CONFIG_HOME`) или
`%APPDATA%\just` (Windows). Именно там `just --global-justfile` (`just -g`) ищет файл.

Приоритет: **`local` перекрывает `group`, `group` — `global`**. Держится он на
неочевидном правиле just: при `set allow-duplicate-recipes` побеждает **первое**
определение рецепта, а не последнее, — поэтому `init` ставит импорты в обратном порядке:

```just
import? 'local.just'
import  'group.just'
import  'global.just'
```

Одноимённый рецепт в `local.just` — способ переопределить общую команду на одной машине;
`init` и `just_new` явно сообщают, когда такое перекрытие возникает, чтобы оно не было
незаметным.

## Структура репозитория

```
.
├── init.sh / init.ps1          развёртывание (Debian/Linux и Windows)
├── just_new.sh / just_new.ps1  сохранить последнюю команду как рецепт
├── Config/
│   ├── global.just             команды для всех машин
│   ├── env.example             заглушки общих переменных окружения
│   ├── example/                группа «example»
│   │   ├── group.just          команды группы
│   │   └── env.example         заглушки переменных группы
│   └── none/                   пустая группа — только общие команды
│       └── group.just          файл-заглушка без рецептов
└── README.md
```

## Установка

### Debian/Linux

```bash
git clone <repo> ~/ops/just
cd ~/ops/just
./init.sh example            # example — имя каталога в Config/
./init.sh --shell example    # то же плюс запись интеграции в ~/.bashrc
source ~/.bashrc
```

### Windows

Нужен PowerShell 7 (`pwsh`) и право создавать симлинки — включите режим разработчика
(Параметры → Система → Для разработчиков) либо запускайте от администратора.

```powershell
git clone <repo> C:\ops\just
cd C:\ops\just
.\init.ps1 example
.\init.ps1 -WithShell example   # плюс запись интеграции в профиль
```

`init` без ключа `--shell` / `-WithShell` ничего не дописывает в ваш профиль, а печатает
готовый блок — вставьте его сами.

Что делает `init`:

1. проверяет just (нужна версия **1.35 или новее**) и при необходимости ставит его:
   `apt-get`, иначе официальный установщик в `~/.local/bin`; на Windows — winget, scoop, cargo;
2. пишет основной `justfile` с тремя импортами и переменными `repo`, `group`, `config_dir`;
3. создаёт симлинки на `global.just` и файл выбранной группы;
4. создаёт `local.just`, если его ещё нет (существующий не трогает);
5. собирает `env` из `*.example` и закрывает права (`600` / доступ только вам);
6. пишет `state.env` — по нему `just_new` находит репозиторий, группу и каталог конфигов;
7. печатает список перекрытых рецептов.

Повторный запуск безопасен: `local.just` и `env` не перезаписываются, прежний `justfile`
сохраняется как `justfile.bak`.

## Повседневное использование

```bash
j                 # список команд (алиас из блока интеграции)
j ping            # выполнить рецепт
j logs app 500    # рецепт с аргументами
j sync            # git pull --ff-only в репозитории
j where           # какие репозиторий, группа и каталог конфигов используются
```

Без алиаса: `just --justfile ~/.config/just/justfile --working-directory . <рецепт>`.
`--working-directory .` важен — иначе рецепты выполняются в каталоге justfile.

## just_new — сохранить выполненную команду

Аналог функции `prev` из [pet](https://github.com/knqyf263/pet): команда уже отработала,
вы поняли, что она нужна — сохраняете её не переписывая.

```bash
just_new                   # взять последнюю команду из истории
just_new -- ls -la /srv    # взять команду из аргументов
just_new -p                # только напечатать блок, ничего не записывать
```

```powershell
just_new                            # последняя команда из истории
just_new -Command 'Get-Service ssh'
just_new -Print
```

`just_new` спросит имя рецепта и описание (описание становится подсказкой в `just --list`)
и допишет рецепт **в `local.just`** — единственный файл, куда он пишет.

Почему это функция, а не просто скрипт: истории родительского шелла процесс-потомок не
видит, поэтому `just_new.sh` подключается через `source` в `~/.bashrc`, а `just_new.ps1` —
дот-сорсингом в профиль (это и делает `init --shell`).

Перед записью проверяются все три файла:

| Ситуация | Что произойдёт |
| --- | --- |
| имени нигде нет | запишет молча |
| имя есть в `local.just` | спросит подтверждение и заменит прежний блок целиком |
| имя есть в `group.just` / `global.just` | предупредит, что общая команда будет локально перекрыта, и предложит подтвердить, ввести другое имя или отменить |
| имя совпало с `alias` | откажется: дубль алиаса ломает разбор конфига целиком |

После записи `just_new` проверяет, что just разбирает конфигурацию, и при ошибке
откатывает изменение из `.bak`.

**В файлы репозитория `just_new` не пишет никогда.** Общие команды правятся редактором
в каталоге проекта; чтобы перенести туда готовый рецепт, используйте `-p` / `-Print`
и вставьте напечатанный блок.

## Группа «none»

Машине нужны только общие команды из `global.just`? `init` всё равно требует группу —
для этого случая есть пустая:

```bash
./init.sh none
```

Своих переменных у неё нет, поэтому рядом с `group.just` нет и `env.example` — `init`
просто пропустит его при сборке `env`.

## Как завести свою группу

```bash
cp -r Config/example Config/myservers
$EDITOR Config/myservers/group.just
git add Config/myservers && git commit -m "группа myservers"
./init.sh myservers
```

Имя каталога и есть имя группы. Машина одновременно принадлежит одной группе.

### Что происходит при `init` с другой группой

| Что | Что с ним станет |
| --- | --- |
| `group.just` | симлинк перенаправляется на файл новой группы |
| `global.just` | не меняется |
| `justfile` | перегенерируется (в нём меняется `group := ...`), прежний остаётся как `justfile.bak` |
| `state.env` | обновляется: `just_new` и рецепты `egroup`/`where` начинают видеть новую группу |
| `local.just` | **не трогается** — машинные команды переезд группы переживают |
| `env` | **не трогается**: переменные новой группы сами не появятся, лишние от старой не исчезнут |

Последнее — единственное место, где нужна ручная работа: `init` сообщит о смене группы
и перечислит ключи, которых в `env` не хватает или которые в нём лишние. Дописывать чужой
файл с реальными значениями скрипт не станет. Полностью пересобрать `env` из заглушек можно,
удалив его перед запуском:

```bash
rm ~/.config/just/env && ./init.sh <новая-группа>
```

## Секреты

В `*.just` и в git не попадает ни одного реального значения:

- в репозитории лежат только `Config/env.example` и `Config/<группа>/env.example`
  с заглушками и комментариями;
- `init` собирает из них `<каталог конфигов>/env`, закрывает права и больше его не трогает;
- justfile подключает этот файл через `set dotenv-path`, значения приходят в рецепты как
  переменные окружения: `"$API_TOKEN"`, а не `{{API_TOKEN}}` — подстановка `{{ }}` видна
  в трассировке и в `just --dry-run`, переменная шелла — нет;
- добавили ключ в `*.example` — на машинах при следующем `init` он попадёт в список
  «в env нет ключей из *.example»; дозаписывать в чужой `env` скрипт не станет.

Пароли и токены в `local.just` тоже не пишем: это тот же текстовый файл, только без git.

## Грабли

- **CRLF ломает всё.** Файл, отредактированный на Windows без нормализации, даёт на Debian
  невнятные ошибки разбора, а shebang-рецепт — `bad interpreter: /bin/bash^M`. В репозитории
  лежит `.gitattributes` с `* text=auto eol=lf`; после пакетных правок скриптами смотрите
  `git diff --stat` — дифф во весь файл на точечной правке и есть флип концов строк.
- **`cd` не переживает конец строки:** каждая строка рецепта выполняется в своём шелле.
  Нужен общий контекст — `cmd1 && cmd2` в одной строке или shebang-рецепт.
- **Симлинки на Windows** требуют режима разработчика или прав администратора. Жёсткая
  ссылка не спасает: репозиторий и профиль обычно на разных томах.
- **Побеждает первое определение рецепта, а не последнее.** Интуиция «последний импорт
  главнее» неверна; именно поэтому в сгенерированном justfile `local.just` импортируется
  первым. Меняя порядок импортов руками, вы меняете приоритет на обратный.
- **Версия just.** Нужна 1.35+: раньше не было `set allow-duplicate-variables`, без которого
  переменная с одним именем в двух файлах ломает разбор.
- **Одноимённые рецепты под разные ОС** оформляются атрибутами `[unix]` / `[windows]` —
  это не дубликаты, just сам выберет вариант.
- **Атрибуты и комментарии — часть рецепта.** `just_new`, заменяя рецепт, удаляет и строки
  `#`/`[...]` над ним; при ручной правке `local.just` помните о том же.

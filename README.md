# Алиасы команд через just

Репозиторий с настройками [just](https://just.systems) и скриптами развёртывания:
общие команды приезжают на машины из git, машинные остаются на машине.

## Как устроено

На машине just работает с одним глобальным `justfile`, который импортирует три файла:

| Файл в каталоге конфигов | Что это | Откуда берётся |
| --- | --- | --- |
| `global.just` | команды для всех машин | симлинк на `Config/global.just` |
| `group.just`  | команды группы машин   | симлинк на `Config/<группа>/group.just` |
| `local.just`  | команды только этой машины | обычный файл, создаётся пустым |

Каталог конфигов — `~/.config/just` (Linux, с учётом `XDG_CONFIG_HOME`) или
`%APPDATA%\just` (Windows). Именно там `just --global-justfile` (`just -g`) ищет файл.

Приоритет: **`local` перекрывает `group`, `group` — `global`**. Держится он на
неочевидном правиле just: при `set allow-duplicate-recipes` побеждает **первое**
определение рецепта, а не последнее, — поэтому `init` ставит импорты в обратном порядке:

```just
import? 'local.just'
import  'group.just'
import  'global.just'
```

Одноимённый рецепт в `local.just` — способ переопределить общую команду на одной машине;
`init` и `just_new` явно сообщают, когда такое перекрытие возникает, чтобы оно не было
незаметным.

## Структура репозитория

```
.
├── init.sh / init.ps1          развёртывание (Debian/Linux и Windows)
├── Scripts/                    функции для оболочки; их подключает блок интеграции init
│   ├── just_new.sh / .ps1      сохранить последнюю команду как рецепт
│   ├── just_dir.sh / .ps1      сохранить каталог как псевдоним для go_dir
│   ├── go_dir.sh / .ps1        перейти в каталог по псевдониму (с автодополнением)
│   └── just_complete.sh / .ps1 автодополнение для just, j и jg
├── Config/
│   ├── global.just             команды для всех машин
│   ├── env.example             заглушки общих переменных окружения
│   ├── example/                группа «example»
│   │   ├── group.just          команды группы
│   │   └── env.example         заглушки переменных группы
│   └── none/                   пустая группа — только общие команды
│       └── group.just          файл-заглушка без рецептов
└── README.md
```

## Установка

### Debian/Linux

```bash
git clone <repo> ~/ops/just
cd ~/ops/just
./init.sh example            # example — имя каталога в Config/
./init.sh --shell example    # то же плюс запись интеграции в ~/.bashrc
source ~/.bashrc
```

### Windows

Нужен PowerShell 7 (`pwsh`) и право создавать симлинки — включите режим разработчика
(Параметры → Система → Для разработчиков) либо запускайте от администратора.

```powershell
git clone <repo> C:\ops\just
cd C:\ops\just
.\init.ps1 example
.\init.ps1 -WithShell example   # плюс запись интеграции в профиль
```

`init` без ключа `--shell` / `-WithShell` ничего не дописывает в ваш профиль, а печатает
готовый блок — вставьте его сами.

Что делает `init`:

1. проверяет just (нужна версия **1.48 или новее**) и при необходимости ставит его:
   `apt-get`, иначе официальный установщик в `~/.local/bin` (с `--force`: он иначе отказывается
   перезаписывать существующий файл); на Windows — winget, scoop, cargo. Если just уже лежит в
   `~/.local/bin`, но самого каталога нет в `PATH` (Debian добавляет его через `~/.profile`
   только если он существовал на момент логина), он находится там и повторно не ставится;
   с ключом `--shell` блок интеграции сам добавит каталог в `PATH`;
2. пишет основной `justfile` с тремя импортами и переменными `repo`, `group`, `config_dir`;
3. создаёт симлинки на `global.just` и файл выбранной группы;
4. создаёт `local.just`, если его ещё нет (существующий не трогает);
5. собирает `env` из `*.example` и закрывает права (`600` / доступ только вам);
6. пишет `state.env` — по нему `just_new` находит репозиторий, группу и каталог конфигов;
7. печатает список перекрытых рецептов.

Повторный запуск безопасен: `local.just` и `env` не перезаписываются, прежний `justfile`
сохраняется как `justfile.bak`.

## Повседневное использование

Блок интеграции заводит два алиаса:

| Алиас | Что это | Какие команды |
| --- | --- | --- |
| `j` | `just` | рецепты `justfile` текущего проекта |
| `jg` | `just -g` | наши глобальные: `global.just`, `group.just`, `local.just` |

```bash
jg                 # список команд
jg ping            # выполнить рецепт
jg logs app 500    # рецепт с аргументами
jg sync            # git pull --ff-only в репозитории
jg where           # какие репозиторий, группа и каталог конфигов используются
j build            # рецепт justfile проекта, если он есть
```

Ключ `-g` (`--global-justfile`) заставляет just взять глобальный `justfile` из каталога
конфигов (`~/.config/just` или `%APPDATA%\just`) вместо поиска в текущем каталоге и выше —
путь указывать не нужно. Рецепты при этом выполняются в каталоге вызова. Совмещать `-g` с
`--working-directory` нельзя: just отвечает `cannot be used with`.

Эта же причина стоит за `-g` внутри самих рецептов: `help` и `default` в `global.just`
вызывают `just -g --list`, иначе голый `just --list` искал бы файл в текущем каталоге.

### Автодополнение (Tab)

Блок интеграции подключает `Scripts/just_complete.sh` / `Scripts/just_complete.ps1` — они включают
дополнение для `just` и обоих алиасов:

| Что набрано | Что предлагается |
| --- | --- |
| `just <Tab>`, `j <Tab>` | флаги и рецепты justfile текущего каталога |
| `jg <Tab>` | рецепты **глобального** justfile, флаги и присваивание переменных (`config_dir=`) |
| `jg --ju<Tab>` | `--justfile`, `--justfile-name` |

Список не зашит в скрипт: при нажатии Tab сам `just` разбирает набранную строку и
отвечает (`just --completions bash` / `powershell` — динамическое дополнение, есть с 1.48).
Поэтому новые флаги и рецепты появляются без правки конфигурации, а описания рецептов
видны как подсказки (в PowerShell — в меню выбора).

Для алиасов этого недостаточно: бинарник должен видеть в строке настоящую команду, а не
имя алиаса, а у `jg` в набранном тексте нет ключа `-g` — рецепты искались бы в justfile
текущего каталога. Обработчик перед вызовом заменяет первое слово: `j` → `just`,
`jg` → `just -g`. Без `init` дополнение можно
включить вручную: `source <(just --completions bash)` (bash) либо
`just --completions powershell | Out-String | Invoke-Expression` (PowerShell) — тогда
будет работать только `just`.

## just_new — сохранить выполненную команду

Аналог функции `prev` из [pet](https://github.com/knqyf263/pet): команда уже отработала,
вы поняли, что она нужна — сохраняете её не переписывая.

```bash
just_new                   # взять последнюю команду из истории
just_new -- ls -la /srv    # взять команду из аргументов
just_new -p                # только напечатать блок, ничего не записывать
```

```powershell
just_new                            # последняя команда из истории
just_new -Command 'Get-Service ssh'
just_new -Print
```

`just_new` спросит имя рецепта и описание (описание становится подсказкой в `just --list`)
и допишет рецепт **в `local.just`** — единственный файл, куда он пишет.

Почему это функция, а не просто скрипт: истории родительского шелла процесс-потомок не
видит, поэтому `Scripts/just_new.sh` подключается через `source` в `~/.bashrc`, а `Scripts/just_new.ps1` —
дот-сорсингом в профиль (это и делает `init --shell`).

Перед записью проверяются все три файла:

| Ситуация | Что произойдёт |
| --- | --- |
| имени нигде нет | запишет молча |
| имя есть в `local.just` | спросит подтверждение и заменит прежний блок целиком |
| имя есть в `group.just` / `global.just` | предупредит, что общая команда будет локально перекрыта, и предложит подтвердить, ввести другое имя или отменить |
| имя совпало с `alias` | откажется: дубль алиаса ломает разбор конфига целиком |

После записи `just_new` проверяет, что just разбирает конфигурацию, и при ошибке
откатывает изменение из `.bak`.

**В файлы репозитория `just_new` не пишет никогда.** Общие команды правятся редактором
в каталоге проекта; чтобы перенести туда готовый рецепт, используйте `-p` / `-Print`
и вставьте напечатанный блок.

## go_dir — переход в каталог по псевдониму

```bash
go_dir                    # список псевдонимов с описаниями
go_dir dir_project        # cd в каталог, на который указывает псевдоним
go_dir dir_<Tab>          # автодополнение имён
```

Псевдоним — обычный рецепт just из группы `go_dir`, который печатает **один путь**:

```just
# Папка проекта
[group('go_dir')]
dir_project:
    @echo '/home/workers/ParserService'
```

Лежать он может в любом из трёх файлов: `global.just` и `group.just` — для общих путей
(правятся в репозитории), `local.just` — для путей только этой машины. Источник всегда
глобальный justfile (`just -g`), поэтому команда работает из любого каталога и не зависит
от `justfile` проекта. Описание в списке и в подсказке Tab — комментарий над рецептом.

Это функция, а не скрипт: `cd` из дочернего процесса не меняет каталог оболочки, поэтому
`Scripts/go_dir.sh` / `Scripts/go_dir.ps1` подключаются блоком `init --shell` так же, как `just_new`.

Что делает команда:

- **Запускает только рецепты группы `go_dir`.** Иначе `go_dir restart` выполнил бы
  произвольный рецепт, а не перешёл в каталог. Чужое имя — отказ и список доступных.
- **Проверяет вывод рецепта:** ровно одна непустая строка (иначе ошибка); пробелы и `\r`
  по краям отрезаются; ведущая `~` раскрывается в домашний каталог — кавычки в
  `echo '~/x'` сами её не раскрывают.
- **Ничего не ломает при неудаче:** рецепт упал, путь пустой или каталога нет — текущий
  каталог не меняется, показывается причина. При успехе молчит, как `cd`.

Ограничения: рецепт без параметров (с параметрами в список не попадает), не `[private]`
(приватные скрыты из `just --list`, по нему и строится список), вызывать можно по имени
рецепта, а не по `alias` из justfile. Для отладки есть переменная `GO_DIR_JUSTFILE`: если
она задана, вместо `-g` берётся указанный justfile.

### just_dir — завести псевдоним

Парный к `just_new`: тот сохраняет команду, этот — каталог. Писать рецепт руками не нужно:

```bash
cd /srv/app
just_dir                          # псевдоним для текущего каталога: спросит имя и описание
just_dir /var/log                 # для указанного каталога
just_dir -n logs -d "Логи"        # без вопросов
just_dir -p                       # только напечатать блок, ничего не писать
```

```powershell
just_dir                          # текущий каталог
just_dir C:\srv\app -Name app -Desc 'Проект'
just_dir -Print
```

Имя по умолчанию — `dir_` + последний компонент пути (`/srv/My App` → `dir_My_App`), его
подтверждает Enter. Результат — рецепт из примера выше, после чего сразу работает
`go_dir <имя>`.

Правила те же, что у `just_new`:

- **Пишет только в `local.just`** — путь принадлежит этой машине. Общие псевдонимы правятся
  редактором в репозитории; перенести готовый блок туда помогает `-p` / `-Print`.
- **Имя проверяется по всем трём файлам.** Своё имя в `local.just` — спросит подтверждение
  и заменит рецепт целиком; рецепт из `group.just` / `global.just` — предупредит, что запись
  создаст локальное переопределение (и псевдоним поведёт в другое место, чем на остальных
  машинах); совпадение с `alias` — откажет.
- **Откатывает запись**, если just после неё не разбирает конфигурацию.
- Каталог должен существовать; путь с одинарной кавычкой не поддерживается — такой путь
  нельзя безопасно вставить в `echo '…'`.

Без терминала (в скрипте) имя обязательно: `-n` / `-Name`, перезапись — `-f` / `-Force`.
`just_dir.*` подключает хелперы `just_new.*` сам, поэтому порядок строк в блоке интеграции
не важен.

## Группа «none»

Машине нужны только общие команды из `global.just`? `init` всё равно требует группу —
для этого случая есть пустая:

```bash
./init.sh none
```

Своих переменных у неё нет, поэтому рядом с `group.just` нет и `env.example` — `init`
просто пропустит его при сборке `env`.

## Как завести свою группу

```bash
cp -r Config/example Config/myservers
$EDITOR Config/myservers/group.just
git add Config/myservers && git commit -m "группа myservers"
./init.sh myservers
```

Имя каталога и есть имя группы. Машина одновременно принадлежит одной группе.

### Что происходит при `init` с другой группой

| Что | Что с ним станет |
| --- | --- |
| `group.just` | симлинк перенаправляется на файл новой группы |
| `global.just` | не меняется |
| `justfile` | перегенерируется (в нём меняется `group := ...`), прежний остаётся как `justfile.bak` |
| `state.env` | обновляется: `just_new` и рецепты `egroup`/`where` начинают видеть новую группу |
| `local.just` | **не трогается** — машинные команды переезд группы переживают |
| `env` | **не трогается**: переменные новой группы сами не появятся, лишние от старой не исчезнут |

Последнее — единственное место, где нужна ручная работа: `init` сообщит о смене группы
и перечислит ключи, которых в `env` не хватает или которые в нём лишние. Дописывать чужой
файл с реальными значениями скрипт не станет. Полностью пересобрать `env` из заглушек можно,
удалив его перед запуском:

```bash
rm ~/.config/just/env && ./init.sh <новая-группа>
```

## Секреты

В `*.just` и в git не попадает ни одного реального значения:

- в репозитории лежат только `Config/env.example` и `Config/<группа>/env.example`
  с заглушками и комментариями;
- `init` собирает из них `<каталог конфигов>/env`, закрывает права и больше его не трогает;
- justfile подключает этот файл через `set dotenv-path`, значения приходят в рецепты как
  переменные окружения: `"$API_TOKEN"`, а не `{{API_TOKEN}}` — подстановка `{{ }}` видна
  в трассировке и в `just --dry-run`, переменная шелла — нет;
- добавили ключ в `*.example` — на машинах при следующем `init` он попадёт в список
  «в env нет ключей из *.example»; дозаписывать в чужой `env` скрипт не станет.

Пароли и токены в `local.just` тоже не пишем: это тот же текстовый файл, только без git.

## Грабли

- **CRLF ломает всё.** Файл, отредактированный на Windows без нормализации, даёт на Debian
  невнятные ошибки разбора, а shebang-рецепт — `bad interpreter: /bin/bash^M`. В репозитории
  лежит `.gitattributes` с `* text=auto eol=lf`; после пакетных правок скриптами смотрите
  `git diff --stat` — дифф во весь файл на точечной правке и есть флип концов строк.
- **`cd` не переживает конец строки:** каждая строка рецепта выполняется в своём шелле.
  Нужен общий контекст — `cmd1 && cmd2` в одной строке или shebang-рецепт.
- **Симлинки на Windows** требуют режима разработчика или прав администратора. Жёсткая
  ссылка не спасает: репозиторий и профиль обычно на разных томах.
- **Побеждает первое определение рецепта, а не последнее.** Интуиция «последний импорт
  главнее» неверна; именно поэтому в сгенерированном justfile `local.just` импортируется
  первым. Меняя порядок импортов руками, вы меняете приоритет на обратный.
- **Версия just.** Нужна 1.48+. Ограничивают три возможности: `set allow-duplicate-variables` —
  без него переменная с одним именем в двух файлах ломает разбор; атрибут `[default]` (1.43);
  динамическое автодополнение (1.48): до него `--completions` отдавал статический скрипт, в
  который нельзя подставить `-g` для `jg`.
- **Рецепт по умолчанию задаёт `[default]`, а не имя `default`.** Без атрибута just запускает первый
  рецепт корневого файла, а импортированные в расчёт не берёт: `default` в `global.just`
  без атрибута даёт `justfile contains no default recipe`. Определение `default` в основном
  justfile перекрыло бы рецепт из `global.just`, поэтому `init` его туда не пишет. Двух `[default]`
  быть не может: just отвечает `duplicate [default] attribute`.
- **Одноимённые рецепты под разные ОС** оформляются атрибутами `[unix]` / `[windows]` —
  это не дубликаты, just сам выберет вариант.
- **Атрибуты и комментарии — часть рецепта.** `just_new`, заменяя рецепт, удаляет и строки
  `#`/`[...]` над ним; при ручной правке `local.just` помните о том же.
